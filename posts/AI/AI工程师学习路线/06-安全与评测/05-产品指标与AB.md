## 〇、贯穿案例：小智的「CSAT 涨了，GMV 跌了」

沿用 [《在线与离线评测》](04-在线与离线评测.html) 的电商客服「小智」。v2.2 上线后一个月，产品组汇报：

- CSAT 从 4.0 涨到 **4.3**（+7.5%）；
- 客服主管私下说：**「退款率涨了 4 个点，GMV 跌了 1.2%」**；
- 算法组复查：「v2.2 的提示词鼓励'理解用户情绪'，模型在用户抱怨退款时更愿意同意」。

指标涨了，业务赔了。

这是典型的 **「代理指标优化」**——CSAT 是「用户对这一次会话的感受」，但被当作「业务好」的唯一代理，**与「业务结构是否健康」脱节**。下面所有设计都围绕「怎么不让这种事再发生」展开。

## 一、产品指标是什么：不是「模型分」，是「业务结果」

### 1.1 模型分 ≠ 产品分

| 模型分 | 产品分 |
|--------|--------|
| 离线黄金集准确率 | 任务解决率 |
| RAG faithfulness | 升级人工率 |
| 幻觉率 | CSAT / NPS |
| PPL | 成本/会话、ROI |
| LLM-as-judge | GMV / 退款率 / 复购率 |

模型分是「模型答得对不对」，产品分是「**用户活儿干完了没**」。

> 一条铁律：**没有上产品指标前，别动模型**——否则改了半年发现业务没动。

### 1.2 北极星指标与代理指标的区别

| 维度 | 北极星 | 代理 |
|------|--------|------|
| 是不是业务最终结果 | 是 | 不是 |
| 能不能直接决策 | 能 | 仅供参考 |
| 反应速度 | 慢（需要业务结果） | 快（短期可看） |
| 例 | GMV、净推荐值 NPS、留存 | CSAT、点赞数、点击率 |

> 北极星 = 「业务能不能活下去」；代理 = 「看着像在变好」

### 1.3 客服 Bot 的北极星是什么

> **净任务完成率（net resolution rate，NRR）= 任务完成率 − 误完成率**

- **任务完成率**：模型独立解决、无需人工；
- **误完成率**：模型「答了」但用户实际没拿到结果（重复问、抱怨、人工复接）；
- **净任务完成率**才是客服 Bot 的北极星——它同时惩罚「不办」与「乱办」。

小智 v2.2 的「CSAT 涨 GMV 跌」就是「净任务完成率跌」的具体表现：模型「答得漂亮」但业务出问题。

### 1.4 落地示例：北极星指标计算（Node.js + TS）

```typescript
// metrics-north-star.ts
export async function northStar(startDate: string, endDate: string) {
  const conversations = await db.conversation.findMany({ where: { dateRange: [startDate, endDate] } });
  let resolved = 0; let falseResolved = 0;

  for (const c of conversations) {
    // 任务完成：用户没有再问，且没转人工
    if (!c.repeatQuery && !c.routedToHuman) resolved++;
    // 误完成：用户 24h 内重复问过同类问题，或触发退款/投诉
    if (c.repeatQuery || c.complaintFlag) falseResolved++;
  }
  const total = conversations.length;
  return {
    total,
    resolutionRate: resolved / total,                 // 期望高
    falseResolutionRate: falseResolved / total,       // 期望低
    netResolution: (resolved - falseResolved) / total, // 北极星
  };
}
```

## 二、指标树：体验 / 质量 / 成本 / 安全

### 2.1 指标树骨架

```
                          净任务率（北极星）
                            │
        ┌────────────┬─────────┴─────────┬────────────┐
        ▼            ▼                   ▼            ▼
       体验         质量                成本          安全
   CSAT / 重复问率  任务正确率         成本/会话     S1 触发率
   TTFT P95       工具调用成功率       GPU 利用率    误杀率
   流式顺滑度       幻觉率             退款率        拒答率
```

### 2.2 四层指标的具体定义

| 层 | 指标 | 定义 | 期望 |
+----|------|------|------|
| **体验** | CSAT | 用户对会话评分 | 高 |
|  | 重复问率 | 24h 内同类问题重复问的占比 | 低 |
|  | TTFT P95 | 首 token 时延 P95 | 低（< 1.5s） |
| **质量** | 任务正确率 | 抽样人工评「答对」的占比 | 高（> 90%） |
|  | 工具调用成功率 | 工具调用成功 / 总调用 | 高（> 99%） |
|  | 幻觉率 | 抽样人工评「幻觉」的占比 | 低（< 5%） |
| **成本** | 成本/会话 | 单次会话 LLM 成本 | 低（业务预算内） |
|  | 退款率 | 触发的退款 / 总订单 | 业务合理范围 |
|  | GMV | 带动/未带动 GMV | 高 |
| **安全** | S1 触发率 | 数据外泄 / 资损 / 法律风险 | **零容忍** |
|  | 误杀率 | 误杀 / 拦截命中 | 低 |
|  | 拒答率 | 拒答 / 总请求 | 业务合理范围 |

> 关键：**「重复问率」是最被忽视的体验指标**——用户重复问 = 上一轮没解决。

### 2.3 落地示例：指标看板（Node.js + TS）


## 三、A/B 与互斥层：提示 / 模型 / 检索怎么同时试

### 3.1 互斥层（mutex layer）原则

A/B 的最大陷阱：「同时改两样东西，看不出谁起了作用」。

工程解法是 **互斥层**：把多个改动放在 **正交的层**，每层独立随机：

| 层 | 改的东西 | 例子 |
+|------|---------|------|
| **L1 提示词** | system prompt | v2.2 旧 vs v2.3 新 |
| **L2 模型** | 模型选择 | gpt-4o-mini vs claude-haiku |
| **L3 检索** | 检索策略 | BM25 vs 混合检索 |
| **L4 护栏** | 护栏版本 | strict / standard |
| **L5 工具** | 工具实现 | A 工具 vs B 工具 |

> **一次只在一个层做实验**——其它层固定。否则实验结果归因不清。

### 3.2 互斥层设计与分层实验

```typescript
// ab-layers.ts
interface Experiment {
  id: string;
  layer: "prompt" | "model" | "retrieval" | "moderation" | "tool";
  variants: string[];   // ["v2.2", "v2.3"]
  trafficPct: number;   // 0.05 起步
  primary: string;      // 北极星指标
  secondary: string[];  // 防御性指标
}

export const EXPERIMENTS: Experiment[] = [
  { id: "exp-prompt-2026-09", layer: "prompt", variants: ["v2.2", "v2.3"], trafficPct: 0.05, primary: "netResolution", secondary: ["csat", "refundRate"] },
  { id: "exp-model-2026-10",  layer: "model",  variants: ["gpt-4o-mini", "claude-haiku"], trafficPct: 0.10, primary: "netResolution", secondary: ["cost", "latency"] },
];
```

> **关键约束：同时最多 1 个 layer 在跑**——L1 跑期间关掉 L2、L3 的实验。

### 3.3 A/B 与互斥层实验的最小可行流程

```
┌────────────────┐    ┌──────────────┐    ┌──────────────┐
│ 1. 假设       │ → │ 2. 选 layer  │ → │ 3. 起 5%    │
│ "改 X 会使 Y↑" │    │ L1 / L2 / L3 │    │ canary 24h   
└────────────────┘    └──────────────┘    └──────────────┘
                                                   │
┌────────────────┐    ┌──────────────┐    ┌──────────▼──────┐
│ 6. 决策        │ ← │ 5. 决策会议  │ ← │ 4. 升 50% / 100% │
│ 全量 / 回滚 / 暂搁│   "达标 / 不达标"│    │ 看指标决定       │
└────────────────┘    └──────────────┘    └─────────────────┘
```

### 3.4 落地示例：A/B 路由（Node.js + TS）

```typescript
// ab-router.ts
export async function routeToVariant(userId: string, expId: string): Promise<string> {
  const exp = await expStore.get(expId);
  if (!exp || exp.status !== "running") return "control"; // 不在跑：全走对照
  // 1) hash 用户 → bucket
  const bucket = hash(`${userId}:${expId}`) % 100;
  // 2) trafficPct 内才进实验
  if (bucket >= exp.trafficPct * 100) return "control";
  // 3) 实验内 50/50 分配
  const variantIdx = bucket % exp.variants.length;
  return exp.variants[variantIdx];
}
```

### 3.5 A/B 必看的对比（白盒）

| 维度 | A 组 | B 组 |
|------|------|------|
| **样本量** | 实际样本 | 实际样本 |
| **基线指标** | CSAT / 解决率 | CSAT / 解决率 |
| **二级指标** | 成本 / 延迟 / 拒答 | 成本 / 延迟 / 拒答 |
| **细分子群** | VIP / 普通 / 新客 | VIP / 普通 / 新客 |
| **保护指标** | S1 / 误杀 | S1 / 误杀 |

> A/B 报「总体涨 5%」**不够**——必须分群看（VIP 涨 2% vs 普通涨 12% 是不同故事）。

## 四、样本量与显著性直觉：什么时候能下结论

### 4.1 为什么要算样本量

样本太少 → 偶然性主导，**结论不可信**；样本太多 → 错过决策窗口，**错过市场**。

**最少样本量**取决于四个东西：

1. **基线率**（baseline rate）；
2. **最小可检测效应**（MDE，minimum detectable effect）；
3. **显著性水平**（α，通常 0.05）；
4. **统计功效**（1 − β，通常 0.80）。

### 4.2 样本量直觉快表

| 基线率 | 基线 | MDE | 每组需要 |
+--------|------|------|----------|
| 任务解决率 | 70% | +3% | ~6,500 / 组 |
| 任务解决率 | 70% | +5% | ~2,400 / 组 |
| CSAT | 4.0 | +0.2 | ~400 / 组 |
| 拒答率 | 5% | -1% | ~4,800 / 组 |
| 退款率 | 4% | -0.5% | ~12,000 / 组 |

> 一句话：**业务量大的指标（解决率 / 拒答率）样本量低**；**业务量小的指标（退款率）样本量高**。

### 4.3 落地示例：样本量计算（Node.js + TS）

```typescript
// sample-size.ts
export function sampleSize(p: number, mde: number, alpha = 0.05, power = 0.8) {
  // 双比例检验样本量（Z-test）
  const zAlpha = 1.96;   // alpha=0.05 双尾
  const zBeta  = 0.84;    // power=0.8
  const p1 = p;
  const p2 = p + mde;
  const pBar = (p1 + p2) / 2;
  const numerator = Math.pow(zAlpha * Math.sqrt(2 * pBar * (1 - pBar)) + zBeta * Math.sqrt(p1*(1-p1) + p2*(1-p2)), 2);
  return Math.ceil(numerator / Math.pow(mde, 2));
}
// sampleSize(0.70, 0.03) -> 6529
// 实战：客服日均 2 万会话，每组 6500 ≈ 7-8 小时可拿
```

### 4.4 显著性直觉：什么时候能下结论

| 情况 | 怎么办 |
+------|--------|
| **跑够样本，p < 0.05** | 可以下结论 |
| **跑够样本，p ≥ 0.05** | 「无显著差异」，不要下「新版本更好」 |
| **样本不够但趋势明显** | **不能下结论**，要么等要么升流量 |
| **两组样本都涨** | 检查分流是否真的随机（hash 打偏 = 实验失败） |
| **A 涨 B 跌** | 可能是「互斥层冲突」，检查是否有其它层在跑 |

> **早停是大忌**——跑到一半「看着像 A 好」就停是统计陷阱。

## 五、警惕「代理指标」优化：只追点赞的反面

### 5.1 代理指标的三个陷阱

| 陷阱 | 例子 | 后果 |
+------|------|------|
| **指标易优化** | CSAT：模型只讲好话 | 实际任务完成率下降 |
| **指标偏短期** | 点赞率：用户当场点赞 | 但三天后退款 |
| **指标偏表面** | 「回复长度」：越长越好 | 浪费成本，无实质效果 |

### 5.2 代理指标识别清单

> 问自己四个问题：
>
> 1. **这个指标涨，业务一定变好？**（不是 → 代理）
> 2. **这个指标能主动优化吗？**（能 → 警惕）
> 3. **优化它会让用户/业务付出代价吗？**（会 → 警惕）
> 4. **过去三个月它与北极星的相关性？**（< 0.7 → 警惕）

> 小智 v2.2 的 CSAT 就是第 2 条——能主动优化（多说好话），代价是 GMV 跌。

### 5.3 多指标对齐：「目标矩阵」

不要只看一个指标——用一个 **目标矩阵** 强制看多维度：

| 指标 | 权重 | 期望方向 | 上版本 | 新版本 | Δ |
|------|------|----------|--------|--------|---|
| 净任务完成率 | 30% | ↑ | 0.61 | 0.63 | +0.02 |
| 成本/会话 | 20% | ↓ | $0.018 | $0.014 | -$0.004 |
| CSAT | 15% | ↑ | 4.0 | 4.3 | +0.3 |
| S1 触发 | 20% | ↓ | 0 | 0 | 0 |
| 退款率 | 15% | ↓ | 0.04 | 0.05 | +0.01 |

> 加权总分 = 0.30×+1 + 0.20×+1 + 0.15×+1 + 0.20×0 + 0.15×-1 = **0.30**（不一定上）——CSAT 涨 +0.3 但退款率涨 0.01 被对冲。

### 5.4 落地示例：目标矩阵自动算分（Node.js + TS）

```typescript
// goal-matrix.ts
interface GoalRow { metric: string; weight: number; want: "up" | "down"; old: number; neu: number }

export function score(rows: GoalRow[]): number {
  // 每个指标一到 [-1, +1]，再按权重求和
  return rows.reduce((sum, r) => {
    const delta = (r.neu - r.old) / Math.max(Math.abs(r.old), 1e-9);
    const sign = r.want === "up" ? 1 : -1;
    return sum + r.weight * sign * delta;
  }, 0);
}
// score([
//   { metric: "netResolution", weight: 0.3, want: "up", old: 0.61, neu: 0.63 },
//   { metric: "costPerConv",    weight: 0.2, want: "down", old: 0.018, neu: 0.014 },
//   { metric: "csat",           weight: 0.15, want: "up", old: 4.0, neu: 4.3 },
//   { metric: "s1Hits",         weight: 0.2, want: "down", old: 0, neu: 0 },
//   { metric: "refundRate",     weight: 0.15, want: "down", old: 0.04, neu: 0.05 },
// ]) -> 0.30
```

## 六、端到端落地示例：四周建起小智指标与实验体系

### 6.1 四周排期

| 周 | 动作 | 产出 | 指标变化 |

| W3 | A/B 路由 + 互斥层 + canary 5%；样本量计算器 | 实验平台 v3 | 实验闭环 |
| W4 | 显著性自动判定 + 实验终止保护；一次只跑一个 layer 强约束 | 实验治理 v4 | 实验不再错 |

+|------|------|------|
