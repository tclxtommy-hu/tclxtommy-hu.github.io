## 〇、穿案例：小智 SaaS 化的两个事故

电商客服「小智」从单租户转 SaaS 多租户，两个真实事故：

| # | 场景 | 后果 | 修复 |
|---|------|------|------|
| 1 | RAG 检索过滤器没传租户 ID | 租户 A 的用户查到租户 B 的私货文档，误判产品 | 向量库所有检索必须带 `tenant_id` 过滤 |
| 2 | 一个租户脚本死循环烧 Token | 其他 20 个租户全被限流 | 租户级信号量 + 配额隔离 |

**关键直觉**：多租户不是「多个单租户凑一起」，是 **从头到脚每层都要问「这个资源是哪个租户的」**。

## 一、隔离维度清单

### 1.1 七层隔离

```text
应用层 ──── 租户路由、UI 隔离
├ API 层 ──── 鉴权、租户上下文传递
├ 限流层 ──── 租户配额、舱壁隔离
├ 业务逻辑层 ── 业务校验、租户过滤
├ 数据层 ──── 向量库、记忆、文件、KV
├ 工具层 ──── ACL、权限
└ 日志层 ──── 租户标签、PII 脱敏
```

**任何一个层漏了，串租户就可能**——不是「哪层最重要」，是「每层都重要」。

### 1.2 隔离强度分级

| 强度 | 描述 | 适用场景 |
|------|------|---------|
| **共享池 + 标签过滤** | 同一 DB / 模型池，靠 tenant_id 字段过滤 | 多数租户、中小 SaaS |
| **共享池 + 命名空间** | DB schema 隔离 / collection 隔离 | 中型 SaaS、保密要求中等 |
| **独立实例** | 每个租户一套 DB / 一套模型 | 金融、医疗、政企 |

小智选**共享池 + 标签过滤**——成本可接受，工程量小，足够保证合规。

## 二、向量库 / 记忆 / 文件的租户键设计

### 2.1 向量库的强制过滤

**核心原则**：所有检索 query 必须带 `tenant_id`，且不可被业务绕过。

```typescript
interface VectorSearchInput {
  tenantId: string;          // 必传，来自鉴权上下文
  query: string;
  topK: number;
  threshold: number;
}

async function vectorSearch(input: VectorSearchInput): Promise<Doc[]> {
  if (!input.tenantId) throw new Error("tenantId required");

  // 嵌入
  const vec = await embed(input.query);

  // 检索：强制带 tenant_id 过滤
  const results = await vectorStore.search({
    vector: vec,
    topK: input.topK,
    filter: {
      must: [
        { key: "tenant_id", match: { value: input.tenantId } },   // ←关键
        { key: "deleted", match: { value: false } },
      ],
    },
  });

  return results.map((r) => r.payload);
}
```

### 2.2 写入路径也带（防止脏数据）

写入路径必须带 `tenant_id`，否则下游检索会查不到：

```typescript
async function upsertDoc(input: UpsertInput): Promise<void> {
  if (!input.tenantId) throw new Error("tenantId required");

  await vectorStore.upsert({
    id: `${input.tenantId}:${input.docId}`,   // ID 加租户前缀
    vector: await embed(input.content),
    payload: {
      ...input.content,
      tenant_id: input.tenantId,               // ← payload 也要带
      created_at: Date.now(),
    },
  });
}
```

### 2.3 对话记忆的租户隔离

```typescript
interface ChatMemory {
  tenantId: string;
  userId: string;
  messages: Message[];
}

async function getMemory(tenantId: string, userId: string): Promise<Message[]> {
  // 路径也带 tenant_id
  return redis.lrange(`memory:${tenantId}:${userId}`, 0, -1);
}

async function pushMemory(tenantId: string, userId: string, msg: Message) {
  await redis.rpush(`memory:${tenantId}:${userId}`, JSON.stringify(msg));
  await redis.expire(`memory:${tenantId}:${userId}`, 86400 * 7); // 7 天过期
}
```

### 2.4 文件存储的租户路径

```typescript
// 路径模板：s3://bucket/tenants/{tenantId}/{userId}/{filename}
async function uploadFile(tenantId: string, userId: string, file: Buffer) {
  const key = `tenants/${tenantId}/${userId}/${hash(file)}.${ext}`;
  return s3.putObject({ Bucket: BUCKET, Key: key, Body: file });
}
```

## 三、检索过滤漏了租户 ID 会发生什么

这是本题第一个学习要点的核心——答案是**信息泄露 + 决策错误 + 合规事故**。

### 3.1 场景复盘（小智事故 1）

```typescript
// 错误代码
async function searchDocs(query: string) {
  const vec = await embed(query);
  return vectorStore.search({ vector: vec, topK: 5 });   // 没有 tenant_id
}

// 用户甲是「某家具品牌」租户，用户乙是「某家电品牌」租户
// 用户甲查「产品维修」→ 检索返回了家电品牌的内部返修率数据
// 小智以「内部返修率 23%」为依据回答 → 用户甲看到竞品数据 → 商业纠纷
```

### 3.2 后果分级

| 后果等级 | 场景 |
|---------|------|
| **轻度** | 返回了无关文档，答案质量差 |
| **中度** | 返回了竞品 / 同行 / 同业的文档，商业敏感 |
| **重度** | 返回了 PII / 商业秘密 / 法律文档，合规事故 |

### 3.3 防御三层

```text
防御 1：强制参数（编译期）
  └─ TypeScript 上把 tenantId 标为 required

防御 2：服务端上下文注入（运行期）
  └─ 中间件从 JWT / API Key 提取 tenantId
  └─ 业务代码调用 searchDocs 时，SDK 自动注入 tenantId
  └─ 业务代码不能手动传其他租户 ID

防御 3：DB 层 ACL（数据期）
  └─ 向量库 / DB 用 Row-Level Security
  └─ 按数据库账号隔离，账号只能查自己 tenant_id 的数据
```

### 3.4 测试覆盖

CI 必须有「串租户」专项测试：

```typescript
describe("cross-tenant data leak", () => {
  it("租户 A 检索不到租户 B 的文档", async () => {
    await upsertDoc({ tenantId: "B", docId: "secret", content: "租户 B 机密" });
    const results = await vectorSearch({ tenantId: "A", query: "机密", topK: 10 });
    expect(results.find((r) => r.docId === "secret")).toBeUndefined();
  });

  it("不传 tenantId 应报错", async () => {
    await expect(vectorSearch({ query: "x" } as any)).rejects.toThrow();
  });

  it("JWT 篡改 tenantId 应被拒", async () => {
    const fakeJWT = forgeJWT({ userId: "u", tenantId: "A" }, "B");  // 假冒 A 访问 B
    await expect(api.searchDocs("x", fakeJWT)).rejects.toThrow();
  });
});
```

## 四、工具 ACL 与权限设计

### 4.1 工具的租户授权

```typescript
interface ToolPermission {
  toolName: string;
  allowedTenants: "all" | string[];   // 哪些租户能调
  tenantToolAllowList?: Record<string, string[]>;  // 租户级工具白名单
  maxCallsPerSession?: number;
}

const TOOL_ACL: ToolPermission[] = [
  {
    toolName: "submit_refund",
    allowedTenants: "all",
    maxCallsPerSession: 3,
  },
  {
    toolName: "query_internal_erp",
    allowedTenants: ["enterprise_a", "enterprise_b"],   // 限制租户
  },
  {
    toolName: "send_email",
    allowedTenants: "all",
    tenantToolAllowList: {                                // 按租户定制
      tenant_a: ["send_email_to_self"],
      tenant_b: ["send_email_to_external"],
    },
  },
];
```

### 4.2 网关层的统一校验

```typescript
async function checkToolPermission(
  tenantId: string,
  toolName: string,
  sessionId: string,
): Promise<void> {
  const acl = TOOL_ACL.find((a) => a.toolName === toolName);
  if (!acl) throw new ToolNotFound();

  // 租户白名单
  if (acl.allowedTenants !== "all" && !acl.allowedTenants.includes(tenantId)) {
    throw new ToolNotAllowedForTenant();
  }

  // 租户级工具白名单
  if (acl.tenantToolAllowList && !acl.tenantToolAllowList[tenantId]?.includes(toolName)) {
    throw new ToolNotAllowedForTenant();
  }

  // 会话级配额
  if (acl.maxCallsPerSession) {
    const count = await redis.incr(`tool_calls:${sessionId}:${toolName}`);
    if (count > acl.maxCallsPerSession) throw new ToolQuotaExceeded();
  }
}
```

### 4.3 工具串数据防控

工具拿到参数后还要**业务校验**，不能信任上游：

```typescript
async function queryOrder(orderId: string, tenantId: string, userId: string): Promise<Order> {
  const order = await db.query("SELECT * FROM orders WHERE id = ?", [orderId]);

  if (!order) throw new OrderNotFound();
  if (order.tenant_id !== tenantId) {                   // ← 业务校验
    log.warn("cross_tenant_query_attempt", { orderId, tenantId, actualTenant: order.tenant_id });
    throw new OrderNotFound();   // 故意返回 not found，不告诉调用方是「串租户」
  }
  if (order.user_id !== userId) throw new OrderNotFound();

  return order;
}
```

**关键实践**：**不告诉调用方是「串租户」**——避免泄露「这个订单存在、但你不能看」这种侧信道信息。

## 五、共享模型池的限流与嘈邻效应

### 5.1 嘈邻效应的本质

**嘈邻效应**（ **noisy neighbor** /ˈnɔɪzi ˈneɪbər/ ）：一个租户的异常流量 / 资源消耗，干扰其他租户的体验。

LLM 应用中常见嘈邻源：

| 嘈邻源 | 影响 |
|--------|------|
| 某租户脚本死循环发请求 | 整个共享模型的 QPS 被占 |
| 某租户单请求带超长上下文 | 所有人延迟上涨 |
| 某租户多 Agent 深度嵌套 | 思考 token 暴涨，所有人费用上涨 |

### 5.2 防御：租户级信号量 + 配额

```typescript
class TenantQuota {
  private semaphores = new Map<string, Semaphore>();
  private tokensPerMin = new Map<string, number>();

  constructor(
    private perTenantConcurrent: number = 5,
    private perTenantTpm: number = 100_000,    // 每分钟 100k tokens
  ) {}

  async check(tenantId: string, estTokens: number): Promise<void> {
    // 1. 并发限流
    if (!this.semaphores.has(tenantId)) {
      this.semaphores.set(tenantId, new Semaphore(this.perTenantConcurrent));
    }
    await this.semaphores.get(tenantId)!.acquire(2000);  // 等最多 2s

    // 2. 配额限流（令牌桶）
    const used = this.tokensPerMin.get(tenantId) ?? 0;
    if (used + estTokens > this.perTenantTpm) {
      this.semaphores.get(tenantId)!.release();
      throw new TenantTpmQuotaExceeded();
    }
    this.tokensPerMin.set(tenantId, used + estTokens);
  }

  release(tenantId: string): void {
    this.semaphores.get(tenantId)?.release();
  }
}
```

### 5.3 配额分级（商业化等级）

| 等级 | TPM | 单请求 | 价格档 |
|------|:---:|:---:|:---:|
| 免费版 | 50k / 月 | 8k tokens | $0 |
| 标准版 | 500k / 月 | 16k tokens | $99/月 |
| 企业版 | 5M / 月 | 32k tokens | $999/月 |
| 定制 | 协商 | 协商 | 协商 |

### 5.4 公平调度：加权队列

不能让「大租户」把小租户挤出队列：

```typescript
class FairScheduler {
  private queues = new Map<string, Request[]>();   // tenantId → requests
  private weights = new Map<string, number>();

  enqueue(tenantId: string, req: Request, weight: number) {
    this.weights.set(tenantId, weight);
    if (!this.queues.has(tenantId)) this.queues.set(tenantId, []);
    this.queues.get(tenantId)!.push(req);
  }

  dequeue(): Request | null {
    // 加权轮询：小租户也分配到至少 1/权重 的机会
    const totalWeight = Array.from(this.weights.values()).reduce((s, w) => s + w, 0);
    let target = Math.random() * totalWeight;
    for (const [tenantId, weight] of this.weights) {
      target -= weight;
      if (target <= 0) {
        const queue = this.queues.get(tenantId)!;
        if (queue.length === 0) continue;
        return queue.shift()!;
      }
    }
    return null;
  }
}
```

## 六、日志与计量如何避免跨租户 PII

这是本题第二个学习要点的核心——答案是**租户级日志隔离 + 自动脱敏 + 计量分离**。

### 6.1 日志隔离的三层

```text
第 1 层：日志分类
  ├── 业务日志（按 tenantId 索引）
  ├── 审计日志（全局，但按租户 tag 过滤）
  └── 调试日志（默认带 PII 风险，上线关闭）

第 2 层：日志存储
  ├── 每租户独立索引 / collection / partition
  └── 跨租户查询默认拒绝（需 admin 权限）

第 3 层：日志脱敏
  ├── PII 字段自动 hash 替换
  ├── 高敏字段默认不入日志
  └── 调试日志 TTL 严格控制
```

### 6.2 PII 自动脱敏中间件

```typescript
interface LogEntry {
  ts: string;
  tenantId: string;
  traceId: string;
  model: string;
  messages: Message[];
  response?: string;
}

const PII_PATTERNS = [
  { pattern: /\d{17}[\dXx]/g, replacement: "[ID_REDACTED]" },        // 身份证
  { pattern: /1[3-9]\d{9}/g, replacement: "[PHONE_REDACTED]" },       // 手机号
  { pattern: /\d{16,19}/g, replacement: "[CARD_REDACTED]" },         // 银行卡
  { pattern: /[\w.]+@[\w.]+/g, replacement: "[EMAIL_REDACTED]" },     // 邮箱
];

function sanitizeMessage(text: string): string {
  let s = text;
  for (const { pattern, replacement } of PII_PATTERNS) {
    s = s.replace(pattern, replacement);
  }
  return s;
}

function safeLog(entry: LogEntry): LogEntry {
  return {
    ...entry,
    messages: entry.messages.map((m) => ({
      ...m,
      content: typeof m.content === "string" ? sanitizeMessage(m.content) : m.content,
    })),
    response: entry.response ? sanitizeMessage(entry.response) : undefined,
  };
}
```

### 6.3 计量的租户级隔离

```typescript
interface TenantMeter {
  tenantId: string;
  windowStart: number;
  windowHours: number;
  inputTokens: number;
  outputTokens: number;
  costUsd: number;
  requestCount: number;
}

async function recordUsage(tenantId: string, input: number, output: number, cost: number) {
  await redis.hIncrBy(`usage:${tenantId}:${currentHour()}`, "input_tokens", input);
  await redis.hIncrBy(`usage:${tenantId}:${currentHour()}`, "output_tokens", output);
  await redis.hIncrByFloat(`usage:${tenantId}:${currentHour()}`, "cost_usd", cost);
  await redis.hIncrBy(`usage:${tenantId}:${currentHour()}`, "request_count", 1);
  await redis.expire(`usage:${tenantId}:${currentHour()}`, 86400 * 30);   // 保留 30 天
}
```

### 6.4 跨租户日志查询的权限

| 角色 | 能查 |

## 七、端到端落地示例：四周迭代

小智 SaaS 化 4 周节奏：

| 周 | 任务 | 工具栈 | 完成标准 |
|----|------|--------|----------|
| W1 | 隔离清单：列七层 × 三强度，决议选「共享池 + 标签」 | 内部 wiki | 隔离决策书 |
| W2 | 数据层隔离：向量库、记忆、文件全部带 tenant_id | 中间层 + 改造 | 「串租户」测试 100% 通过 |
| W3 | 限流 + 配额：租户级信号量 + 公平调度 + 配额分级 | 网关 + 调度器 | 某租户死循环只影响自己 |
| W4 | 日志 + 计量：自动脱敏 + 租户索引 + 审计 | 日志中间件 + 计量管道 | PII 0 泄露 + 计量准确 |

**四周后的指标**（小智 SaaS 上线一年）：

- 串租户事故：0 起
- 嘈邻干扰投诉：年 8 起 → 0 起
- 商业化计费纠纷：0 起
