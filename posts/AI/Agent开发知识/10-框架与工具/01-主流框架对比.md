# 主流框架对比

> 最后修改时间：2026-11-13 13:44

> 一句话定义：对比 LangChain/LangGraph、AutoGen、CrewAI、LlamaIndex 等主流 Agent 框架的特点与选型。

> 📌 2026 年末格局变化（相对本文初稿）：
>
> 1. **LangChain / LangGraph 均已发布 1.0**：LangChain 1.0 把高层 Agent 抽象收敛为 `create_agent`（底层就是 LangGraph），「LangChain vs LangGraph 选哪个」的问题基本消失——写 Agent 用 `create_agent`，要精细控制就下沉图；
> 2. **微软整合**：AutoGen 与 Semantic Kernel 合并进 **Microsoft Agent Framework**（2025 年底 GA），新项目直接用 Agent Framework，AutoGen 进入维护模式；
> 3. **官方 SDK 崛起**：OpenAI Agents SDK（Python + TypeScript）与 Google **ADK** （Agent Development Kit）分流了部分「轻量编排」需求；
> 4. **Agno**（原 Phidata）以性能和简洁在 Python 社区增长很快。

## 1. 框架全景

| 框架 | 出品 | 技术栈 | 特点 | 适合 |
|------|------|--------|------|------|
| LangGraph | LangChain | Python / TypeScript | 显式状态图、可控循环 | 需精细流程控制 |
| LangChain | 社区 | Python / TypeScript | 生态最全、工具丰富 | 快速原型、通用 |
| Microsoft Agent Framework | 微软 | Python / .NET | AutoGen + Semantic Kernel 合并，多 Agent + 企业集成 | 微软系 / 企业 .NET |
| CrewAI | 社区 | Python | 角色化、易用 | 角色分工任务 |
| LlamaIndex | 社区 | Python / TypeScript | RAG 强、Agent 支持 | 知识密集 Agent |
| Pydantic AI | Pydantic 团队 | Python | 类型安全、结构化 | 生产、强校验（详解见 [02-PydanticAI详解.md](02-PydanticAI详解.md)） |
| OpenAI Agents SDK | OpenAI | Python / TypeScript | 官方、轻量 | OpenAI 生态 |
| Google ADK | Google | Python / Java | 官方、与 Gemini/A2A 深度集成 | Google 生态、多 Agent |
| Agno | 社区 | Python | 高性能、实例化快、内存占用低 | 性能敏感、简洁 API |

## 2. 详细对比

### LangGraph
- 把 Agent 流程建模为**状态图**（节点+边），显式控制循环与分支。
- 支持人在环上、持久化、子图。
- 适合需精细流程控制与可观测的生产场景。
- 学习曲线中等。

### LangChain
- 生态最全：工具、记忆、检索、模型适配最丰富。
- 1.0 起 Agent 抽象收敛为 `create_agent`（底层基于 LangGraph），旧 `AgentExecutor` 进入历史。
- 适合快速原型与通用集成。

### Microsoft Agent Framework（原 AutoGen）
- AutoGen 与 Semantic Kernel 合并后的统一框架：保留 AutoGen 的多 Agent 对话能力，吸收 SK 的企业连接器与进程模型。
- 原 AutoGen（v0.2/v0.4）进入维护模式，老项目迁移需按官方迁移指南走。
- 适合微软技术栈团队做多 Agent 协作与企业集成。

### CrewAI
- 以"角色 + 任务 + 流程"组织，API 简洁。
- 上手快，适合角色分工明确的任务。
- 复杂流程控制不如 LangGraph。

### LlamaIndex
- RAG 能力强，Agent 与检索深度集成。
- 适合知识密集型 Agent（文档问答、研究）。

### Pydantic AI
- 类型安全、结构化输出与依赖注入为一等公民；适合生产边界清晰的单 Agent。
- 与 LangGraph 常互补（编排用图、节点用类型安全 Agent）。详解见 [02-PydanticAI详解.md](02-PydanticAI详解.md)。

## 3. 选型建议

| 需求 | 推荐 |
|------|------|
| 精细流程控制、生产 | LangGraph |
| 快速原型、通用 | LangChain |
| 多 Agent 协作 | Microsoft Agent Framework / CrewAI / Google ADK |
| 知识密集 | LlamaIndex |
| 类型安全生产 | Pydantic AI |
| OpenAI 生态 | OpenAI Agents SDK |
| 性能敏感、轻量 | Agno |

## 4. 其他考量
- **模型支持**：是否支持多模型/本地模型。
- **可观测**：是否集成 LangSmith/Langfuse。
- **MCP 支持**：能否消费 MCP Server。
- **持久化**：是否支持状态持久化与恢复。
- **社区与文档**：活跃度与文档质量。

## 5. 学习要点
- 没有银弹，按需求选框架。
- LangGraph 在可控性与生产化上最强。
- 多 Agent 选 Agent Framework/CrewAI/ADK，知识密集选 LlamaIndex。
- 官方 SDK（OpenAI Agents SDK、Google ADK）适合生态内轻量需求，别一上来就堆框架。
