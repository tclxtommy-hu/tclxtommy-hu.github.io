# 产品经理（软件公司）

> 状态：⬜ 待写（骨架已初始化）
> 上游：运营、老板、客户
> 下游：设计师 / 程序员 / 测试
> 核心交付：需求文档、设计需求单、验收记录
> 目标成熟度：L2–L3

## 1. 角色边界

负责：
- 把需求线索收敛成可开发、可验收的 **PRD** /ˌpiː ɑːr ˈdiː/ （ **Product Requirements Document** /ˈprɒdʌkt rɪˈkwaɪəmənts ˈdɒkjumənt/ ，产品需求文档）。
- 维护 **wiki** /ˈwɪki/ 作为唯一需求源，回写所有变更。
- 组织评审、确认优先级、完成验收。

不负责：
- 替设计师定视觉。
- 替程序员定技术方案。
- 替测试下质量结论。

## 2. 日常动作

| 频次 | 动作 | 产出 |
|------|------|------|
| 每周 | 需求澄清与立项 | 澄清清单 + 优先级 |
| 每需求 | 写 PRD | wiki PRD |
| 评审前 | 准备评审包 | 评审材料 |
| 测试后 | 逐条验收 | 验收记录 |

## 4. 交接物模板

### 4.1 wiki PRD 八段

| 段落 | 必填内容 |
|------|----------|
| 背景 | 谁在什么场景遇到什么问题 |
| 目标 | 可量化的业务目标 |
| 范围 | 做什么、不做什么 |
| 流程 | 主流程 + 分支 |
| 验收标准 | 每条可测试、可判定 |
| 边界 | 空 / 错 / 无权限 / 超长 |
| 埋点 | 事件、属性、看板 |
| 上线计划 | 灰度、回滚、通知 |

### 4.2 设计需求单

| 字段 | 说明 |
|------|------|
| 页面清单 | 需要设计的页面 |
| 状态 | 空 / 加载 / 错误 / 无权限 |
| 约束 | 组件库、品牌、适配 |
| 验收标准 | 视觉与交互的判定标准 |
| 参考 | 竞品或历史页面 |
